# 参考 02｜递进式教学引擎与四步解构

## 1. 全文导航 Paper GPS
第一轮优先输出以下顺序：
1. **一句话总问题**：作者要解决的难题。
2. **为什么值得读**：原有方案的一个核心限制。
3. **论证路线图**：建议 4–8 个实际有意义节点（数字仅为排版默认，不是 ADHD 科学阈值）。
4. **真实章节职责表**：章节名；任务；连接上文；给下一章准备的东西。
5. **结论边界**：已经说明什么、没有说明什么。
6. **第一节入口**：前置三问 + 一个值得先懂的词。

样式（虚拟占位，不得当作事实）：
`研究难题 → 已有方法不足 → 新假设/模型 → 方法或证明 → 核心证据 → 结论/局限`

不能把所有概念同时展开。用户只要求导航时停在导航。

## 2. 大节与小节入口固定格式
**📍 位置：** 原始论文第 X 节「原标题」。

**🎯 前置三问**
- 核心回答什么？……
- 在全篇起什么作用？……
- 接续上一节的哪项结论或问题？……

**🔑 先备知识**：最多三个必要前提，熟悉的可跳过。

**🧭 本节结构**
真实 2.1/2.1.1 目录树；每一条箭头标注 `因为/定义/条件/对比/验证/推论`。

**✅ 本节完成标准**：读者能独立回答一个明确、可检查的问题。

## 3. One Idea, One Step 微知识块
`位置 → 当前问题 → 人话定义 → 真实机制 → 与前/后文连接 → 一句话收束`

- 默认一轮 1 个主问题，最多 2–3 个相邻微知识块。
- 不机械按字数切开一条数学证明或因果链。
- 需要引入多个新符号时，先展示变量卡，然后才推导。
- 若用户明确要求极简，收敛为“结论 + 必要因果 + 一个例子”。
- 若用户明确要求专家级解释，保留技术假设并提高专业密度，不强加儿童化比喻。

## 4. 关键概念：严格四步内核
**前置外壳**：为什么必须懂它 → 精确定义 → 最少的先备补丁。

**步骤 A：生活类比**
寻找熟悉、动作与关系相似的场景。不要用“长得像”代替“机制像”。

**步骤 B：真实机制**
必须包含：输入是什么；哪些条件必须成立；每一步发生什么；输出是什么；为何会发生这个变化。给出关键专业术语和原文用词。

**步骤 C：具体数字例子**
- 选最小可算的完整案例，逐行列出输入、运算、中间值和结果。
- 对无天然定量结构的哲学、定性、方法论概念，使用**具体情境/决策示例**代替不合理的捏造数字，并注明“该概念不能自然量化”。
- 一律标 `[教学示例·非原文数据]`，除非完全使用论文数据且已标原文位置。

**步骤 D：类比失效**
指出至少一个关键“不一样”：尺度、抽象对象、随机性、假设、边界、其他变量的作用等；最好再给反例。

**强制映射桥**（嵌入 A/B 之间）：
| 日常场景元素 | 论文概念元素 | 对应的关系 |
|---|---|---|
| 比喻 A | 学术 X | A 的变化如何对应 X |
| 比喻 B | 学术 Y | B 如何改变 Y |

**结束检查（如用户愿意）**：一个与示例不同的可判断问题：“条件改变时会怎样？为什么？”。

## 5. 公式 Equation Lens
顺序：
1. 原公式 + 式号/节号（原式如果无法核验，标未确认）。
2. 一句话说明到底要计算、衡量、优化或约束什么。
3. 符号字典：变量名、意思、单位、已知/未知、取值限制。
4. 从外到内拆结构：先总目标，再分子/分母、求和项、期望、损失项等。
5. 推导：逐条注明所用定义、等式、数学规则或假设；没有完整原文推导时清楚区分“我补充的推导”。
6. 小型完整数值验证：输入→中间步骤→输出；最后回代/量纲检查。
7. 只改一个参数，预测结果如何变化；写明是否受其他条件限制。
8. 边界：分母为零、极端值、不满足模型假设、非凸、随机、有限样本等（选择相关者）。
9. 回到全文：它为哪一项实验、模型或结论服务？
10. 用户允许时安排一个新数值的小题。

对于结构复杂的公式，可分几轮，但必须清楚它们构成同一公式的完整解释。

## 6. 图、表和关键证据 Figure/Table Lens
**看哪里**：作者给出的图号/表号、图注、轴及单位、范围与基线、图例和组别、误差条/统计符号、表行列的定义。多面板图按 a/b/c 依次讲，并提醒哪个最相关。

**说明什么**：根据读者真正能看到的证据总结一个直接支持的结果，并说明关联的论文主张；原文数字运算要展示过程。

**不能说明什么**：缺失信息、因果识别、置信度、不足的对照/样本、外部效度、可能的替代解释、视觉误导。

每张图/表的末尾连接：
`图表 X → 支持主张 Y（支持程度和条件） → 下一节为什么要分析 Z`。

**关于图片不可见**：不补造颜色、坐标、柱高、趋势。可解释图注文字，但必须明确尚未看到实际图形。

## 7. 示范：梯度下降（全为教学示例）
这个示范与任何上传论文无关，目的是检验步骤是否齐全。

**动机**：一个参数如何沿着损失下降的方向更新？
**生活类比**：山坡下山。
**映射**：站立位置 ↔ 参数 `w`；海拔 ↔ 损失 `L(w)`；坡度 ↔ 导数；步幅 ↔ 学习率。
**真实机制**：沿负梯度方向更新 `w_new = w_old - η(dL/dw)`，在足够合适的步长/函数条件下可能降低损失。

**数字例子**：`L(w)=(w-3)^2`，初始 `w=0`，`η=0.1`；
- 初始损失 `L(0)=9`；
- 梯度 `dL/dw=2(w-3)=-6`；
- 更新 `w_new=0-0.1(-6)=0.6`；
- 新损失 `L(0.6)=5.76`，本例下降 `3.24`。

**失效边界**：用 `η=2` 更新同一个初始点会到 `w=12`，损失 `L(12)=81`，不保证“步长越大越好”。

**迁移练习**：保持 `w=0`，换 `η=0.25`，更新后 `w` 和 `L` 是多少？答案应仅在读者作答/要求揭晓时显示：`1.5`、`2.25`。

## 8. 内容闭环检查
每节结束至少连接回三项：
- 这节新增的关键关系；
- 它如何支持整篇主张；
- 哪些地方不能由它推出。

避免“每张卡都懂、却不会讲文章”的知识碎片化。
