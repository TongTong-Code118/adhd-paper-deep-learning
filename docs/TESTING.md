# 功能验收｜Skill 发现、MCP 调用、实际视觉效果

## 1. 本地自动测试（无需 AI 账号）

在仓库根目录：

```bash
python -m pip install -e .
python scripts/sync_platform_skills.py --check
python scripts/validate_repo.py
python -m unittest discover -s tests -v
python scripts/diagnose.py
python scripts/demo.py
```

测试期望：
- MCP initialize 握手响应包含正确协议版本和 `tools` 能力；
- `tools/list` 列出 5 个只读工具；
- 每个工具都返回真实 `image/png` 内容，开头可由 PNG 阅读器识别；
- 通知 `notifications/initialized` 不产生错误响应；
- 源来源说明字段 `source_note` 缺失或关系长度不正确时拒绝输入；
- Skill 三个平台镜像一致；
- `examples/` 产生 5 张可读图片。

## 2. 真实模型行为测试（需要在目标客户端分别进行）

**T1：宏观首轮**
- 给一篇真的论文，要求画总结构图。
- 应收到可见的 PNG，原文标题/顺序正确，当前章高亮。
- 失败：只有 `纯文本` 代码块与箭头。

**T2：章节前置三问**
- 指定 2.1/3.1 等章节。
- 应先解释“回答什么/全文作用/前后承接”，调用 `render_section_flow`。
- 失败：未看原文就补造小节。

**T3：四步概念**
- 提出一个抽象术语，要求生活类比、原理、具体例子与失效边界。
- 应有真正图形，类比和真实机制对应，不把类比写成事实。

**T4：数学与图表**
- 给带明确数值的公式/表，要求全过程计算与三棱镜。
- 应保留单位、来源、统计限制，不对未显示图像描述颜色或高度。

**T5：视觉渲染退路**
- 模拟客户端不支持 MCP 图片显示。
- 模型应明确指出**服务器返回了 PNG，但界面没有显示**，再给实际可见的分块表格，而非粘贴 base64。

**T6：无效输入与来源核验**
- 截图写第二章，但具体标题是 `3.1`；必须承认这一不一致，并在 `source_note` 中注明不能核实的部分。
- 禁止凭空补齐七类因子名、回测收益与 p 值。

**T7：读者自主性**
- 用户说“只给两句、不要图、不要测验”，模型必须服从。
- 用户说“忘了前面”，先显示当前 Paper GPS 的位置、上一节结论与下一步目标。

## 3. 安全与能力边界

- Skill 的**自动触发**与 Tool 的**实际可用**是两个不同测试。
- 离线 MCP 只有 `tools` 子集（stdio）。不接受路径/URL 参数，不会读取本机资料或发网络请求。
- 即使工具输出了成功 PNG，模型根据它写出的任何新的学术事实仍要向原文核验。
- 不能把自评“看懂”当成延迟记忆表现；长期保持需要后续复习与迁移测试。
